# MJ 6.2.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move bizapps-forms to MJ 6.2.0, raise the supported-host floor to 6.2, and land #349, #215 and a magicLink install notice in one PR.

**Architecture:** Pins move in two groups with `bump-pins.sh`: the supported-host peers go to `6.2.0-edge.8`, and the host-tracking pins go to `6.2.0`. The #349 registration change relies on the MJ#4990 fix that only 6.2 has. A new in-process `postInstallModule`/`postUpgradeModule` hook in `forms-server` reuses `checkRespondentReadiness` to print the magicLink instruction.

**Tech Stack:** pnpm 10 / turbo, TypeScript, Vitest (`.spec.ts`), Angular 21, SQL Server (docker `sql-mj-it`:1455), `npx mj` CLI.

**Spec:** `docs/superpowers/specs/2026-11-04-mj-6-2-upgrade-design.md`

## Global Constraints

- Peers in `packages/*`: `^6.2.0-edge.8`. `mjVersionRange`: `>=6.2.0-edge.8 <7.0.0`. Host-tracking pins (`apps/*`, root devDeps, `pnpm.overrides` MJ entries): `6.2.0` / `^6.2.0`.
- Angular untouched: core `21.2.22`, cdk `21.2.14`, tooling `21.2.23`.
- Core frontier after migration: `202611032346`. Before: `202610061630`.
- Never `pnpm install` inside `bizapps-forms` (main checkout). In the **worktree**, an install is allowed: it is a standalone root with its own store, and it gives a CI-faithful build against the published 6.2.0. The shared-workspace install runs only at `~/Projects/mj-dev`.
- Never run CodeGen against `MJ_ATS_Dev`. Never `pkill` by name. Branch harness on :4131 with `MJAPI_PUBLIC_URL=http://localhost:4131`.
- Every build, test and typecheck runs with `TURBO_FORCE=true`, and the summary must show `Cached: 0 cached`.
- **No commit and no push** until Soham asks. Task 9 prepares the commit split.

## Review Focus

1. **A host on 6.2.0 with `magicLink` already enabled:** the hook must stay silent (no false alarm). Test in Task 4.
2. **A host whose `mj.config.cjs` is missing, or throws on load:** the hook prints the instruction plus "could not check", and does not throw. Test in Task 4.
3. **`magicLink` enabled but the respondent role not grantable:** the hook prints the role message, which is the second readiness failure. Test in Task 4.
4. **A Person record on a 6.2 host whose Person form was regenerated (baked grid key):** the Forms panel still hides it. The existing test `hides a baked grid…` must stay green with `relatedJoinField` set (Task 3).
5. **Lockfile with two MJ versions** (a stale `6.1.6` importer): build passes locally but CI has two `@memberjunction/core` copies. Covered by the `uniq -c` check in Task 2.
